## 这是什么

一份**开箱即用的 Hermes 初始化方案**。它解决一个真实痛点：Hermes 装好后默认是个**能力很强但完全不认识你**的"陌生外包"——不知道你的生意、你的标准、你的雷区，会礼貌敷衍、编数据、等你指令。

这套方案让 Hermes 在**首次对话时**就完成对你的画像，把它从"陌生人"变成"懂你、替你扛活、敢反驳你"的 AI Agent 合伙人。

## 两个文件

| 文件 | 给谁 | 作用 |
|------|------|------|
| `hermes_onboarding_guide.md` | Hermes 执行 | 一键初始化的完整执行脚本（Q1~Q9 + 写入映射 + 规则） |
| `hermes_onboarding_methodology.md` | 给人看 | 方法论说明，讲清楚"为什么这么做" |

## 核心特性

- **新用户**：完整初始化，零配置零学习直接上手
- **老用户**：自动增量升级，只补缺的字段，**不重走、不动已有配置**（零副作用）
- **版本机制**：统一版本自适应，后续升级喂新版即增量

## 版本

- v4.0（2026-09-13）｜ 更新日期：2026-09-13

### v4.0 更新说明（贡献方法论·推荐启用）

- **贡献方法论从"可选"改为"推荐启用"**：当话题涉及贡献/自进化/方法论沉淀时，Hermes 主动推荐使用者开启，给出推荐话术（生态共赢 + 纯匿名 + 自动去隐私 + 一句话可关），不再建议"先攒着、暂不开"——除非使用者明确拒绝。让这套方法论被更多使用者验证得越好。

### v3.9 更新说明（贡献方法论·配置化入口）

- **贡献方法论入口改为配置文件承载**：endpoint 与邀请码统一收敛到 `scripts/feedback_contrib.example.json`，文档不再硬编码域名——换邀请码只改这一处配置，用户端启用时自动读取，全自动不变。

### v3.8 更新说明（贡献方法论·档位二）

- **新增贡献方法论（可选启用）**：使用者在长期使用中沉淀的重要方法论，可**匿名推送回馈**（endpoint 与邀请码见 `scripts/feedback_contrib.example.json`，带防伪授权码）——我们审核后进新版迭代，让配置包被更多用户验证过的方法论喂养。启用即自动完成读配置 → 换 key → 登记 → 推送，全程零手动，一句话可关。
- **防投毒机制**：每用户 key 由接收端签发（`/provision`），匿名 UUID + 专属防伪签名；未登记/伪造 key/纯 uuid 全部 401；我们人工审核 inbox 才入新版。
- **去隐私硬要求**：推送前自动剥离服务器IP/本地路径/邮箱/交易/手机号/身份证。

### v3.7 更新说明（自进化机制）

- **新增自进化机制（可选启用）**：使用者启用后，Hermes 每天闲时检测配置包是否有新版，**默认自动静默升级**（也可改为"提示确认"或"不检测"）——升级永远走增量合并、零静默覆盖、随时可关、只补不覆盖。配套 `scripts/check_update.py` 检测脚本。
- **检测脚本**：`scripts/check_update.py` 三层退化检测（releases→tags→README 版本号），只读零副作用。

### v3.6 更新说明（长期进化方法论）

- **新增方法论**：独立判断不顺拐 · 不过度分析 · 画大饼 vs 诚实示弱 · 先研究再出方案 · 交付后停 · 记录使用者特定术语 · 技能 description 是路由唯一信号
- **优化提升**：分层存判据 · 工具失败不编造 · 被打断后先确认状态再执行 · 成本纪律补全（切高级模型后记得切回 · 不默认派活 · 批量前设预算上限 · 只在瞬时错误重试 · 长提示用缓存）
- **精简去重**：合并"幻觉翻车模式"中与现有纪律重复的条目（凭记忆报数→报数字先核实；验证✅≠已修复→核销纪律）
